The plan

Six phases, each one playable

Every phase ends with a build you can open and play, not a pile of unfinished parts. If a phase runs long, we cut features from it, never ship it half-working. Phase 2b was added when you asked for a bigger city.

Phase 2, built

Memory and relationships

Each person used to follow a fixed script. Now they bump into each other, remember it, and act differently the next day. All eight work packages are in.

The one structural change: a day ledger

Today any moment can be computed straight from the seed, which is why catch-up is instant. Once relationships exist, tomorrow depends on what happened today, so that shortcut ends. The fix is to settle each day in order and keep a short record of it. Catch-up then replays missed days one by one, in small batches so a phone never freezes. Plans for the day stay deterministic, so the same seed still gives the same history.

How Phase 2 measured up
  • Met: pairs drift apart within days, and the web and ledger show why. After an argument at a place, the next-day visit rate there fell from 63% to 44% across 300 test cities.
  • Met: leaving or switching away returns the four biggest things that happened, with times, not just a day count.
  • Met: the same seed gives the same history, checked by hashing the ledger.
  • Built but not yet proven: offscreen skipping, sprite warm-up and adaptive resolution are in. Only tested on a software renderer so far, so a real phone check is still owed.
Phase 2b, built

A full town

You asked for the city to grow. We settled on about forty people and more homes in the same district, with no extra map and no new businesses yet. Forty is a different game from three, so most of the work went into making that many people readable.

Forty people means 780 pairs

Three people meant three pairs and a handful of meetings a day. Forty means 780 pairs, about 63 conversations a day, about ten of them arguments, and a phone screen that used to hold three chips. So every part of the interface learned to summarise: counts on rooftops, a searchable people list, a strip of what is happening right now, and red alerts only for the rows that matter. Loading changed too. Replaying every day from day 0 costs 6 to 7 ms a day, so the game now saves the city's memory once a day and resumes from there.

How Phase 2b measured up
  • Met: one seed is still one history. Resuming from a snapshot gives exactly the same state as replaying every day (checked by hashing it), and the snapshot code left the history unchanged across 9 seeds and 25 days.
  • Met: loading stays flat. A day-300 city loads in about 0.47 s instead of 2.15 s on a desktop. A phone will be slower, probably around four times (an estimate).
  • Met: nothing broke. Seven seeds at desktop and phone sizes ran with no console or page errors, and offline reload, the away report and NEW CITY all work.
  • Met, with a note: arguments run at about ten a day town-wide, about five of which clear the bar for a red toast. With cooldowns that is roughly one toast every four real minutes. Every row is still in the ledger.
  • Not yet proven: phone speed. A frame costs about 8 to 12 ms of work on the software renderer I can test with. A real phone check is still owed.
  • Known gaps: a Phase 2 save loads a different town, ledger rows older than the newest 1,800 events keep one line instead of the dialogue, portrait phones leave empty space above and below the board, and settling the next day at 22:30 can cost about a frame on a slow phone.
